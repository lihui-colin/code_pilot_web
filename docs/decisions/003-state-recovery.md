# ADR-003：重启后不接管历史 viewer

- 状态：Accepted
- 日期：2026-08-02

## 背景

状态文件可以保存 viewer PID 和端口，但 PID 会被操作系统复用。管理服务重启后，仅凭历史 PID 或端口无法可靠确认进程所有权。

相比 Zellij Session，code-viewer 实例可以按 repository 重新创建，不需要保证跨管理服务重启持续存在。

## 决策

首版不接管历史 viewer。

启动时读取历史记录，只有同时验证 PID 的命令和启动时间确实属于本服务时，才终止遗留进程。随后清空全部 viewer 和端口记录。用户再次浏览 repository 时创建新实例。

正常收到 `SIGTERM` 时，管理服务停止所有当前管理的 viewer，但保留全部 Zellij Session。

## 后果

- 避免 PID 重用导致终止无关进程。
- 简化代理路由、进程事件监听和端口所有权恢复。
- 管理服务重启后，已打开的 code-viewer 标签页会失效，需要重新从管理页面打开。
- 后续如需 viewer 无缝恢复，应引入外部进程监督器或可验证的实例身份机制，再新增 ADR。
